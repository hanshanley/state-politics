## Claim disposition

The README preserves previous numbers and figures for comparison, but its warning applies to
**every old analytical result**, including stated-versus-filed, outlier, trend, election,
outcome, reuse and roll-call claims. They are unresolved until rebuilt and reviewed.
The old 62% top-1 / 78% top-2 figures do not validate the replacement or establish reliable
topic-specific performance. Source subject-tag agreement is not automatically accuracy,
independent validation, or an upper bound.

The existing 50-plank snapshot is a known, previously inspected diagnostic set. It is not
training data or a fresh blind test. New assistant/local-model judgments, if collected, must
retain that reviewer type and must not be described as human gold.

## Legislative extraction contract

The extractor now stages all eleven bill, sponsorship, action, vote and richer-evidence
tables before promotion. Its source-hashed manifest starts incomplete, existing artifacts
cannot be overwritten, and successful extraction is explicitly **not source completeness
or scientific certification**. An interrupted run retains its staging directory and the
original dump; select a new output directory rather than overwriting its evidence.

PostgreSQL COPY parsing now fails on malformed rows, missing source-table blocks and
unterminated blocks instead of silently dropping evidence. Control escapes and encoded
UTF-8 are preserved. Abstracts, source URLs, versions and version links retain original IDs,
notes and dates with exact bill joins and per-bill availability counts. Empty URL fields
do not count as available references. Snapshot abstracts and signed-act references are
**not automatically filing-time-safe**, and version text has not yet been downloaded.

The extraction manifest intentionally leaves the analytical cutoff unset. Retaining source
context from sessions overlapping 2018 does not mean every retained row belongs in a
2018-onward analytical denominator. Actual dates, missingness and session completeness must
be measured after extraction.

## First actual trained-model diagnostic

The official revision-pinned English ModernBERT-base encoder and classifier head completed
three epochs on `data/labels/cap-initialization-pilot-v2/labels.jsonl`: 5,895 external-coded
training units, batch four, 1,024-token budget, learning rate `2e-5`, seed `20261018`.
The saved `data/models/modernbert-cap-pilot-v1/` reloads through the strict research loader.
Its manifest verifies an actual encoder-parameter update, dataset/code hashes and three
epoch-history entries. This is a real topic-training run, distinct from the earlier
synthetic feasibility checkpoints.

**It has not demonstrated an overall improvement.** The following comparison uses the same
50 provisional assistant-reviewed development units, not independent human gold.
Thresholds were not tuned after inspecting the results: the new model uses its recorded
research defaults of temperature 1.0, confidence 0.8 and margin 0.2; the historical
nearest-description baseline uses cosine similarity 0.2.

| Diagnostic | Historical MiniLM | Trained ModernBERT pilot |
|---|---:|---:|
| Classified / all eligible | 39 / 50 (78%) | 40 / 50 (80%) |
| Correct topics / classified | 19 / 39 (48.72%) | 20 / 40 (50%) |
| Correct topics / all eligible | 19 / 50 (38%) | 20 / 50 (40%) |
| Correct abstentions / reference abstentions | 8 / 20 | 7 / 20 |
| Correct topic or correct abstention / all eligible | 27 / 50 (54%) | 27 / 50 (54%) |
| Bill decision accuracy | 23 / 40 (57.5%) | 22 / 40 (55%) |
| Platform-unit decision accuracy | 4 / 10 (40%) | 5 / 10 (50%) |

The ten platform units come from one Texas Republican document. Three inputs exceed the
legacy model's 256-token budget; its scores are cosine similarities, not calibrated
probabilities. These tiny development slices do not establish representative accuracy,
statistical superiority or publication readiness for either model.

The trained model's 23 reference disagreements comprise 13 accepted inputs whose reference
abstains, seven wrong topics and three missed topics through abstention. It confidently
assigns topics to committee lists, an honorific resolution and a retrospective report.
For example, `DNR-VARIOUS` receives a health prediction above 0.99 despite insufficient
evidence. Raising confidence alone is not an established remedy; substantive boundaries
and rejection need reviewed training evidence, not just a different encoder.

The retained abstract sidecar supplies evidence for 14 of the 40 development bills and six
of the 18 bill errors. A separate, explicitly post-hoc enrichment inspection fed the full
retained abstracts to the unchanged checkpoint. Agricultural overtime changed from
agriculture to labor; expungement changed from macroeconomics to criminal justice.
The honorific resolution still received a substantive topic, and cultural facilities
remained misclassified. Richer text can address some evidence shortages but did not solve
rejection or category support in these inspected cases.

Full error units, original review rationales, both input tiers, source abstract IDs,
predictions and hashes are retained under
`data/processed/topic-pilot-v1/posthoc-evidence-review-v1/`. This targeted inspection is
not a new test set or an improved accuracy estimate. Title-only references are not
automatically valid for enriched text; some previously ambiguous titles now have additional
substantive evidence. Abstract timing is unverified and cannot establish filing-time attention.
No labels, weights or thresholds were changed to obtain a better-looking score.

## Explicit rejection and separate target-domain training

The first pilot was trained only on policy topics: confidence thresholds alone cannot
teach it what a committee list or honorary resolution is. Training now accepts an explicit
null target only for reviewed target evidence with a `non_policy`, `mixed_policy` or
`insufficient_evidence` reason. Unreviewed external "other" codes and unresolved taxonomy
disputes are not converted into rejection examples.

When such examples are present, the head has 21 unchanged policy outputs plus one learned
rejection output. Manifest schema 2 declares the exact output map and rejection support;
schema-1 policy-only checkpoints remain loadable. A winning rejection yields topic null,
not a 22nd counted policy category. Predictions retain the full output map, logits and
rejection probability. Evaluation and development calibration preserve this map and include
reviewed null references in probability losses when that output exists. Existing uncertainty
and chunk-disagreement abstentions remain in force; no automatic certification is added.

All **128 complete inputs** in `data/labels/target-adaptation-pilot-v1/` received explicit
assistant semantic review: 106 were selected for provisional training and 22 quarantined
without labels. Selected training contains 57 policy examples and 49 rejection examples
(40 non-policy, eight insufficient-evidence, one mixed). Every selected record retains its
full input, source binding, reviewer identity/date and individual rationale. Keyword and
length strata were used only to sample additional titles, not to assign their labels:
the sampled "recognizances" bill is substantive criminal justice, for example.

The 50 original development judgments remain unchanged. Their IDs, groups and exact/close
text were reserved; no Texas Republican development document was split into training.
The two additional platform documents are California Democratic 2026 and Texas Democratic
2026-2028, distinct from the legacy diagnostic's California/Texas documents. Legacy diagnostic
texts were also reserved. These checks do not rule out paraphrased bill-family dependence.

`data/labels/cap-target-rejection-pilot-v1/` contains 6,001 training records: the same 5,895
external initialization units plus 106 reviewed target units, with the unchanged 50-unit
development set. Culture still has only ten arts examples; a learned rejection head does
not repair that deficiency or certify mixed-policy detection from one mixed example.
The reviews are assistant judgments, not independent human gold. Rubric disputes, broken
unit boundaries and ambiguous source context remain in the separate quarantine rather
than being silently taught as non-policy. Model quality must be measured after actual
training and reload; the implementation itself is not an accuracy improvement.

### Recoverable discovery runs

The existing crawl has attempted its initial 100 organizations. All 100 archive queries
entered the failure-retry pass; that describes retrieval failures, not missing historical
platforms. Its homepage fetches retained hashes but not the response bodies, and its final
candidate/status files are not written until after retries. This makes an interrupted
run needlessly difficult to recover.

New discovery CLI runs retain homepage bytes in `data/raw/platforms/discovery/`, using
distinct filenames so a later response cannot overwrite earlier evidence. Provenance binds
the stored path, response hash and original retrieval time. Each organization also receives
an atomic JSON checkpoint before the next organization starts. Archive retry snapshots are
separate and preserve both the original live candidates and the retry result, including
explicit failures. Checkpoints include registry/code hashes and the exact run arguments.

The default checkpoint directory sits beside `--out`; `--checkpoint-dir` and `--raw-dir`
allow a separately named run. Existing checkpoint directories are refused. This is durable
recovery evidence, not an automatic resume implementation or completeness certification.
An explicit `--no-wayback` supports bounded live-only supplements without repeated failed
archive requests. Skipped archive searches remain distinguishable from successful searches;
disabling both channels is rejected.
